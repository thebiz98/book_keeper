## 4. Test coverage
Present: TC-SALE-007 (next after SAL-1005), cmb-009 writes then reads settings via repo (not via service/IPC), TC-MOCK-019 mock round trip.
Missing (add): next code on empty DB for each prefix (1001); next code ignores `PUR-OPEN-*`/legacy; create without client code yields sequential codes; create with duplicate code returns typed Conflict (not raw SQL); second customer return without code succeeds; vendor return beyond 1000; ADJ/OPN/RTL sequences per DD-07; preview does not consume numbers (mock too); settings: seeded row present after migrate, update trims/rejects blank, get after update through the service, single row guaranteed; detail views contain unit, pack snapshot, supplier ref, shop profile; party rename behaviour (documented either way); Header test that boot loads persisted shop name.

## 5. Schema and contract delta
- `purchase_transactions.source` plus per-source code sequences; `supplier_invoice_ref` column (DD-25).
- `sale_items`/`purchase_items`: `pack_label`, `pack_quantity` (DD-28); expose `base_unit` in line DTOs.
- `shop_settings`: `CHECK(id=1)`, validation in service; optional extra print fields (e.g. footer) if wanted.
- Services: `next_code(source)` inside tx; remove `transaction_code`/`return_code` from create payloads (or ignore); return the assigned code.
- Detail DTOs: add shop settings (or fetch in UI), original sale code for returns, both return line directions, settlements for returns.
- Frontend: boot-time `getShopSettings` into store; provisional code label; mock parity per DD-27.
