- Mock parity test: same sale payload rejected by mock and by backend (DD-27).

## 5. Schema and contract delta
- CHECK `remaining_quantity >= 0` and `<= quantity` on `purchase_items`; CHECK `current_stock >= 0` on `items` (FR-03 F-13). Note: a CHECK on `current_stock` requires removing the `.max(0.0)` clamps first so errors are visible.
- Service contract: `validate_stock_availability(uow, &[(item_id, base_qty)])` aggregated; `deplete_lots_for_outflow(source_type, source_id, ...)` for ADJUSTMENT / REPLACEMENT / VENDOR_RETURN (DD-11).
- DTOs: `StockAdjustmentPayload.unit_cost`, `adjustment_date` (DD-12); `ReturnItem.line_type`; replacement issued-line payload.
- IPC: preserve typed `InsufficientStockError { item_id, item_name, required, available }` so the UI can render the Negative Stock Alert; commands for lot picker (`get_item_lots`).
- UI store: `addItem`/`setBundle` return a reason plus available count.
