# FR-09 Review: Financial Aggregations & Reports

Reviewer scope: dashboard KPIs, P&L, stock valuation, cash flow, trend, recent transactions, live cash drawer. Read-only review against the aligned design (DD-01/07/13/14/15/21, HLD FR-09 + section 7 + 9.3, LLD 6.10 Metric Definitions, UI/UX 2.1 / Page 1 / Page 10). Overlaps reference FR-01..FR-07 reports by ID and are not re-derived.

## 1. Scope traced

Frontend: `src/pages/DashboardPage.tsx`, `src/pages/ReportsPage.tsx`, `src/components/common/DateRangePicker.tsx`, `src/components/layout/Header.tsx`, `src/store/useAppStore.ts`, `src/types/{api,index,store}.ts`, `src/api/ipc.ts`, `src/api/mock/mockClient.ts`, the `recordCashFlow` callers (NewSalePage, NewPurchasePage, CreditDuesPage, ReturnsAdjustmentsPage).
Backend: `api/report_controller.rs`, `services/impl/report_service_impl.rs` (all 236 lines), `services/contracts/report_service.rs`, `data/contracts/report_repository.rs`, `core/dtos/report_dto.rs`, `services/impl/accounting_service_impl.rs:28-96` (drawer variant), `payment_service_impl.rs`, `sale_service_impl.rs:148-165`, `sale_repo.rs` (list_sales/where_clause), `settlement_repo.rs`, `allocation_repo.rs`, `data/sqlite/migrations.rs` (indexes/schema).
Tests: `tests/report_service_test.rs`, `accounting_service_test.rs` (TC-DUES-003), `e2e_scenarios_test.rs:109`, `e2e_tier3_combinations_test.rs:351,421,477`, `e2e_lifecycle_test.rs:202`. No frontend tests exist for DashboardPage, ReportsPage or DateRangePicker.

Overall: the report layer is a thin in-memory aggregation over `list_*` repo calls. It implements roughly 4 of the 12 LLD metric definitions, none of the DD-13 additions (returns, replacement COGS, inventory losses, purchases net), no `get_recent_transactions`, no period handling in trend, and a cash drawer that bypasses the ledger.

## 5. Schema and contract delta

Schema (from DDs, required by reports): `payment_settlements.kind` + `return_id` + nullable `transaction_id`, `amount_paid > 0` (DD-01); `purchase_transactions.source` (DD-07); `sale_stock_allocations.returned_quantity` (DD-05/13); `stock_outflow_allocations` (DD-11); `return_transactions.settlement_type/total_amount` populated; `return_items.cost_amount/condition/line_type`. Indexes to add: `payment_settlements(settlement_date, transaction_type, kind)`, `purchase_transactions(source, transaction_date)`, `stock_outflow_allocations(source_type, source_id)`.
Contract: `get_recent_transactions(limit)` command + `RecentTransaction` DTO; `PnLReport` -> `{gross_sales, sales_returns, net_sales, cogs, gross_profit, inventory_losses, net_profit, total_purchases}`; `CashFlowReport` add `vendor_refunds_inflow`, drop duplicates; `StockValuationReport` real `categories_breakdown`; `get_sales_purchase_trend(period)` validated enum; remove `total_discounts`, `returns_refunded`, `today_sales`, `today_purchases` duplicates; remove client `recordCashFlow` store API and expose `liveCashInDrawer` only from backend; implement or delete `ReportRepository`.
