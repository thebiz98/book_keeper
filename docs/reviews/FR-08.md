## 4. Test coverage
- TC-INV-004 (inventory_service_test.rs:286-322) asserts stock, allocation qty and cost, but runs against the test-local copy of the service (lines 116-200), not production `InventoryServiceImpl` (FR-04 F-05).
- TC-INV-005 positive adjustment only checks synthetic lot existence; does not assert purchase header fields, absence of vendor ledger effect, or cost fallback.
- TC-FIFO-006 covers multi-lot depletion (good) but no insufficient-stock, fractional or exact-boundary case.
- e2e (scenarios:93, tier3:172) exercise negative adjustment via real service only as setup steps; lifecycle:213 asserts 0 adjustments (rollback), the only failure test.
- Missing: TC-INV-007 (reject zero/over write-off atomically, no adjustment row left), `list_stock_adjustments` pagination/filter/ordering, date validation, reason enum round-trip, inactive item, fractional qty, loss value returned, positive adjustment when item never had a lot (unit_cost required), no frontend tests for the modal/Tab 3/mock parity, no IPC case-conversion test for `reason`.

## 5. Schema and contract delta
- Schema: STOCK_OUTFLOW_ALLOCATION (source_type ADJUSTMENT) replacing `adjustment_stock_allocations`; `purchase_transactions.source`/lot source ADJUSTMENT; CHECK(quantity<>0); reason values migrated to DD-12 strings; optionally store unit_cost on adjustment.
- DTO: `StockAdjustmentPayload` add `unit_cost: Option<f64>`, required date; `AdjustmentReason` 4 variants SCREAMING_SNAKE; response `{adjustment_id, loss_value}`; history view with item name/unit and loss value.
- IPC: `create_stock_adjustment` return shape change; `list_stock_adjustments` DESC ordering, SQL pagination, item name; helper to fetch latest lot cost for prefill (`get_item_lots` exists in spec).
- TS: mirror types (`AdjustmentReason`, payload `unitCost`), mock parity, modal item search + unit cost + date + 4 reasons, dashboard quick action.
