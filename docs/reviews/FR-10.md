## 5. Schema and contract delta

- DTOs: `SaleHistoryRow`, `PurchaseHistoryRow` (add `party_name`, `line_count`, `supplier_invoice_ref`); `SalesHistoryFilter`/`PurchaseHistoryFilter` add `search_query`, accept `ALL`; `PartyListRow {…, outstanding_balance, transaction_count}`; `PartyDueSummary` add `total_invoiced`, `total_paid`; `ReturnsFilter {return_type, start_date, end_date, page, limit}`; unified `Paginated<T>` naming decision (`total` vs `total_count`).
- IPC commands: `list_returns` (DD-21), `get_item_categories` (or distinct from catalog), open-bills-per-party for the dues expand, `get_party_ledger` exposure (DD-21); `list_parties`/`search_parties` change return type.
- Repo signatures: `(Vec<Row>, usize)` for `list_sales`, `list_purchases`, `list_returns`, `list_adjustments`, `list_catalog` (LLD §5.2); remove the double-query count in `get_catalog`.
- Schema: no new columns required; optional indexes (`payment_status`/open balance partial indexes, `(transaction_date DESC, id DESC)`).
- Frontend: shared `useList`/`DataTable` contract (`page`, `limit`, `total`, `onPageChange`, `onSearch`, `error`), local-date helpers, mock parity.
