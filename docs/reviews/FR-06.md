# FR-06 Review: Symmetrical Credit & Dues Management

Overlaps with batch 1 (FR-01/02/03) are referenced by ID, not repeated: ledger lacks `kind`/`return_id`, `transaction_id NOT NULL`, no rounding, `update_balance_due` derives paid from the balance delta, dashboard cash disagrees with the accounting service, typed errors lost over IPC, mock enforces no rules.

## 5. Schema and contract delta
- Schema v2: `payment_settlements` needs `kind`, `return_id`, nullable `transaction_id`, positive amounts (FR-01 delta). Consider an optional `group_id` for lump sums.
- Repos:
  - `PurchaseRepository::list_open_for_party` and `SaleRepository::list_open_for_party`, ordered by `(transaction_date, id)`.
  - A grouped `get_party_due_summary` SQL for both sides.
  - A ledger query joining bills and settlements.
- DTOs:
  - `SettlePaymentPayload` gains `transaction_type` and renames `specific_bill_id` -> `transaction_id` (LLD). The frontend type must follow.
  - `PartyDueSummary` needs a min-date `oldest_bill_date`.
  - `PartyLedgerEntry` needs `kind`, bill code, and reference id.
- IPC: add `get_party_open_bills(party_id)` (or an equivalent bill listing) for the expandable row and the FIFO preview.
- Services:
  - `AccountingService::settle_bill_payment` must validate first, then write via `PaymentService::record_payment` only.
  - `PaymentService::recompute_bill` replaces `update_balance_due` and `reduce_transaction_balance`.
