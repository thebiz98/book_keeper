## 4. Test coverage
- Exists: nothing for items import or backup. Only migration (deferred) tests use the migration path.
- Missing (add): TC-IMP-* per LLD: CSV and XLSX happy path; missing required header; per-row validation (negative, non-numeric, bundle both/neither, units <= 1) with row+field; duplicate name in file; barcode duplicate vs DB/file/bundle; Skip/Overwrite/AddStock semantics (Overwrite never changes stock/base unit); one `OPN-` header with total 0 and lot cost = Purchase Cost; stock cache and low-stock; all-or-nothing rollback (one bad row, nothing persisted); dry-run writes nothing (row counts unchanged); FTS searchable after import.
- Backup tests: file created with timestamp name; second backup in the same minute gets `_2`; never overwrites; non-directory/unwritable destination returns IoError; backup of a WAL DB with uncommitted-to-main-file data contains latest rows; restore-open of backup passes integrity; integrity on corrupted file returns false. Also a test for DB-path resolution with `BOOK_KEEPER_DB_PATH` (extract resolver from main.rs for testability).
- Frontend: no vitest coverage of Settings/import dialog.

## 5. Schema and contract delta
- Schema (from FR-01/DD-07, needed here): `purchase_transaction.source` column + `OPN-` sequence. Consider unique index on `items.barcode` (partial where not null) or app-level check across items and bundles.
- New service `ItemImportService` (`validate_items_import`, `execute_items_import`); DTOs `ImportValidationReport {rows, errors[{row, field, message}], duplicates, newCount}`, `ConflictStrategy`, `ImportSummary {created, updated, skipped, stock_lots_created}`.
- IPC commands: `validate_items_import(file_path)`, `execute_items_import(file_path, strategy)`; keep `backup_database(destination_dir)`, `verify_database_integrity`; add a last-backup field in shop settings (or return metadata) and a default backup dir command. Remove `import_items_from_excel`, exports, migration commands per DD-16.
- Tauri: add `tauri-plugin-dialog` (Rust + JS), `capabilities/default.json` with `dialog:allow-open`/`allow-save`; use `csv` crate (already in Cargo.toml) for CSV.
- main.rs: resolve DB path once (`BOOK_KEEPER_DB_PATH` else `app_data_dir/shop.db`); pass the same path to backup service (already via `build_sqlite_app_state`).
- Mock: `validateItemsImport`, `executeItemsImport` with realistic report; backup naming.
- Entanglement note: `migration_controller.rs` hosts the import commands; `MigrationPage.tsx:212` is the only import UI; `ImportExportServiceImpl` hosts both import and exports; `scan_backup_directory`/`inspect_backup_file` are migration (deferred) not restore.
