## 4. Test coverage
Existing (all backend, linked/cash only): customer restockable return + SALE_REFUND row (-100) (lifecycle); scrap return leaves lot untouched (fifo_strategy); DefectiveReplacement scrap swap asserts only stock stays at 4 (scenarios S3); vendor ReduceDue asserted only through a later P&L (tier3:385). TC-INV-003 and TC-PAY-004 test the primitives. Weak: S3 passes because the swap path is a no-op; the vendor test never checks balance_due; no test asserts return total_amount (which is 0, F-02), the ledger kinds, or the stock cache against lots. Tests always pass `return_code`, hiding F-01. No frontend test for the Returns page; mock tests do not touch returns.
Missing (LLD TC-RET-* / FIFO): linked sale_item mismatch, qty > sold − returned, duplicate lines in one payload, price > sale price, party default/mismatch, linked credit-then-cash remainder (own bill only), unlinked FIFO dues, walk-in cash, vendor credit then REFUND_IN, vendor lot qty cap/FIFO outflow log (TC-FIFO-004/005/007), replacement colour swap (issued line depletion and COGS net = 1 unit), defective swap (scrap to losses), negative/zero qty, rollback on failure midway (e.g. insufficient stock on issued line leaves no partial return), second return gets a distinct code, `list_returns`/`get_return_details`, rounding, P&L/dashboard effect, mock parity.

## 5. Schema and contract delta
- `return_transactions`: `return_type` values CUSTOMER|VENDOR; `settlement_type` REFUND|REPLACEMENT; keep total (money value, 0 for replacement).
- `return_items`: add `line_type (RETURNED|REPLACEMENT_ISSUED)`, `cost_amount`, `unit_cost` for issued lines; unique return code sequences (RET/VRET/RTL).
- `sale_stock_allocations`: `returned_quantity`.
- `STOCK_OUTFLOW_ALLOCATION` table (replaces ADJUSTMENT_STOCK_ALLOCATION).
- `payment_settlements`: `kind`, `return_id`, nullable `transaction_id` (currently NOT NULL, and the code writes 0), drop negative `amount_paid` and `*_REFUND` types.
- `purchase_transactions.source` incl. RETURN (unlinked restock lots).
- DTOs: `CustomerReturnPayload {original_sale_id?, party_id?, settlement_type, returned_items[{item_id, sale_item_id?, quantity, unit_price?, condition, unit_cost?}], issued_items[{item_id, quantity}]}` (no return_code); `VendorReturnPayload` with optional lot; `ReturnResult`; `ReturnDetailView` with lines, `cost_amount`, credits, refunds; `ReturnListRow`/`ReturnsFilter`.
- IPC: add `list_returns(filter)` (service, controller, main.rs, ipc.ts, mock); `get_returnable_lines(sale_id)` (or fold into `get_sale_details`) so the UI can show returnable qty; typed errors.
- Mock: validation, dues/credit logic, vendor refund, returns list/details.
