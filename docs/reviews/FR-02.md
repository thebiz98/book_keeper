## 5. Schema and contract delta
Schema (migration v2): payment_settlements add `kind TEXT NOT NULL`, `return_id INTEGER NULL REFERENCES return_transactions(id)`, make `transaction_id` nullable, enforce `amount_paid > 0` (remove negative-refund convention); sale_items drop `bundle_id` FK and `bundle_quantity`, add `pack_label TEXT NULL`, `pack_quantity REAL NULL`; optional CHECKs on header (balance_due >= 0, status consistent).
DTOs: CreateSalePayload add `payment_status`; make `transaction_code` server-only; CreateSaleItemPayload keeps `bundle_id` as write-time hint; SaleSummaryResponse: stored `paid_amount`, single `change`, header-read-back; SalesHistoryFilter add `search_query`, drop from/to duplicates; new SaleHistoryRow `{id, transaction_code, transaction_date, party_id, party_name, line_count, total_amount, paid_amount, balance_due, payment_status}`; SaleItem/SaleItemDetail expose pack_label/pack_quantity; SaleDetailView settlements carry `kind`.
IPC: `create_sale`, `get_sales_history`, `get_sale_details` return typed AppError (DD-26); `get_sales_history` returns paged SaleHistoryRow; frontend types (src/types/index.ts Sale, SaleItem, api.ts HistoryFilter/CreateSalePayload) and mock updated in lockstep; frontend `invokeCmd` rejects with `{type, details}`.

## Cross-requirement issues noticed
- Dashboard/cash flow (report_service_impl.rs:77-103, accounting_service_impl.rs:30-100): header-based sales cash, `CUSTOMER_SETTLEMENT` type never written, transaction_date vs settlement_date; client-side `recordCashFlow` used by NewPurchasePage, CreditDuesPage, ReturnsAdjustmentsPage with the same pattern (belongs to cash-flow/dashboard reviewer).
- FR-04 dues: `reduce_transaction_balance` and `update_balance_due` (shared with purchases) derive paid from balance deltas; SettlementModal is a lump-sum party flow, no per-bill settle (DD-04).
- FR-03 purchase side repeats bundle_id/bundle_quantity coupling and same UTC-date, code-passing patterns.
- FR-01 inventory: stock cache clamp `.max(0.0)` and strict stock comparison (inventory_service_impl.rs:56, fifo_strategy.rs:21).
